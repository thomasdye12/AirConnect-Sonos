How this build works Architecture & current limits

This is a fork of Philippe44’s AirConnect. The original C application and its RAOP library receive AirPlay and decode ALAC audio. Our changes add room naming directly from the Sonos HTTP API, native UDP output, helper coordination, pause handling and per-room timing calibration.

The selected helper briefly establishes a Sonos receiver session. The receiver is then made independent and the helper is restored, allowing another room to start. Each receiver has its own PCM stream and clock responder. The helper is still required for setup.

The bridge follows AirPlay’s source timestamps with a 75 ms UDP sending lead. The configured receiver latency and room calibration also affect timing; the calibration value is not total end-to-end latency. The latest continuity fix uses a sample-counted cursor to avoid inserting gaps on each audio block.

Rooms configured for HTTP use the original UPnP path: the bridge serves an audio stream and asks Sonos to fetch it with SetAVTransportURI. Native UDP skips that HTTP audio-fetch path. Different AirPlay sources can select different rooms; this is not AirPlay 2 synchronized multi-room playback. Native title/artwork updates and long-term drift compensation remain unfinished.

This dashboard observes systemd, process-owned device locks, the room API and a bounded log tail. It does not control the speakers. Diagnostics include local device addresses, room names and recent log messages.
